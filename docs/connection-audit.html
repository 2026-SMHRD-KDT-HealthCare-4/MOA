2. 버그 · 미연결 · 미실행 — 상세 내용

🔴 [버그 1] medication.ts:66 — createMedication이 guardian_id 자리에 seniorId를 보냄

복약 등록 시 요청 body에 guardian_id: seniorId를 포함하고 있습니다. seniorId를 guardian_id 필드에 그대로 넣은 값입니다. 백엔드는 토큰(JWT)에서 호출자의 신원을 직접 확인하므로 body의 guardian_id는 사용되지 않아 기능은 작동합니다. 그러나 의미가 잘못된 데이터를 보내고 있으며, 나중에 백엔드 로직이 바뀌면 오동작할 수 있습니다.

// frontend/src/api/medication.ts:64-70
body: JSON.stringify({
  senior_id: seniorId,
  guardian_id: seniorId,  // ← seniorId를 guardian_id 자리에 잘못 넣음
  medicine_name: medicineName,
  intake_times: intakeTimes.map(formatTimeForAPI),
  ...
})

수정 방법: guardian_id 필드 자체를 body에서 제거. 백엔드가 토큰에서 직접 guardianId를 추출함.

🟡 [버그 2] MedicationFormPage.tsx:284 — 수정 시 여러 복용시간 중 첫 번째만 업데이트

백엔드는 같은 약이라도 복용시간마다 별도의 medication row로 저장합니다 (예: 혈압약 08:00, 혈압약 20:00 → 2개 row). 그러나 수정 시 resolvedId 하나에 대해 formattedTimes[0](첫 번째 시간)만 PATCH하므로, 2회 이상 복용 약의 나머지 시간대 row는 전혀 업데이트되지 않습니다.

// frontend/src/pages/MedicationFormPage.tsx:282-289
if (isEditMode && resolvedId) {
  await updateMedication(resolvedId, {
    medicine_name: name.trim(),
    intake_time: formattedTimes[0],  // ← 첫 번째 시간만, 나머지 row 미업데이트
    start_date: startDate,
    end_date: endDate || null,
    is_active: enabled,
  });
}

근본 원인: getGroupedMedications()가 같은 약 이름의 여러 row를 하나로 묶어 UI에 보여주는데, 수정 진입 시 id로 첫 번째 row만 넘깁니다. 수정 로직을 "해당 약 이름 + seniorId로 기존 row 전체 삭제 후 재생성" 또는 "여러 medication_id를 받아 각각 PATCH"하는 방식으로 바꿔야 합니다.

🔴 [미연결 1] NotificationCenterPage.tsx — 백엔드 알림 API 전혀 미사용

알림센터 화면이 Zustand store(localStorage)에서만 데이터를 읽고 있습니다. 백엔드에 GET /notification/guardian/me(보호자 알림)와 GET /medication/reminders/me(복약 알림 목록)가 완전히 구현되어 있지만, 이 화면에서 한 번도 호출하지 않습니다.

// frontend/src/pages/NotificationCenterPage.tsx:9
const medications = useMedicationStore(s => s.medications);        // store만
const schedules   = useMedicationStore(s => s.hospitalSchedules);    // store만
// GET /notification/guardian/me  → 호출 없음 ❌
// GET /medication/reminders/me   → 호출 없음 ❌

결과: 백엔드에서 발송된 RISK·MEDICATION·HOSPITAL·INACTIVE 알림이 화면에 전혀 표시되지 않습니다. 고령층이 챗봇에서 "약 먹었어요" 응답을 해도 알림센터가 갱신되지 않습니다.

🟡 [미연결 2] DashboardPage.tsx:12 — 리포트가 환경변수 조건부

보호자 리포트 화면이 EXPO_PUBLIC_AUTH_API_MODE=real 환경변수가 설정된 경우에만 API를 호출합니다. 이 값이 없으면 항상 하드코딩된 샘플 데이터(FALLBACK_REPORT)만 표시됩니다.

// frontend/src/pages/DashboardPage.tsx:12
const REAL_API = process.env.EXPO_PUBLIC_AUTH_API_MODE === "real";

// DashboardPage.tsx:139
if (!REAL_API || !elderlyId) return;  // ← 환경변수 없으면 샘플 데이터만 표시

결과: 실제 음성분석 결과가 DB에 쌓여도 리포트 화면에 반영되지 않을 수 있습니다. .env에 해당 환경변수가 없으면 조건 자체를 제거하거나 기본값을 true로 변경해야 합니다.

🟠 [미연결 3] 긴급알림 — 챗봇에서 키워드 감지만 하고 DB 저장 없음

ChatPage.tsx에서 챗봇 발화에 자살위험·응급 키워드가 감지되면 UI 경고는 표시하지만, 백엔드에 urgent_alert 테이블에 저장하는 API 엔드포인트가 없고 프론트에서도 API 호출이 없습니다.

  • urgent_alert DB 테이블은 존재 (모델 정의 완료)
  • 백엔드에 POST /urgent-alert 엔드포인트 없음
  • 프론트에서 저장 API 호출 없음
  • 결과: 감지된 긴급 상황이 DB에 기록되지 않고, 보호자 알림도 발송되지 않음
